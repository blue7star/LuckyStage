# 通用抽奖小程序首版设计

日期：2026-10-27

## 目标与范围

一个组织者管理多场公司内部或对外活动。每场活动独立配置报名、轮次、奖项与主题。公司自有服务器承载网页后台、抽奖大屏、API 和数据库，经公司配置的公网入口供微信小程序访问。

## 使用者与页面

- 组织者：电脑网页登录、创建活动、配置报名字段与去重字段、导入 CSV 名单、配置抽奖、设置主题、生成小程序码并主持抽奖。
- 参与者：扫描活动小程序码，填写该场活动的表单，查看报名状态和中奖结果。
- 现场观众：大屏显示当前轮次、奖项、中奖者与活动主题。抽奖操作只在已登录后台发起，大屏只读展示。

## 活动模型

每场活动包含标题、时间、说明、报名模式（导入、扫码、两者均可）、报名开放状态、表单字段、唯一去重字段、轮次和主题。字段有稳定键、标题、类型、必填状态；去重字段始终必填。组织者指定一个现有字段用于显示中奖者。活动之间的参与者和结果隔离。

导入文件使用 UTF-8 CSV，首行为与字段标题或键匹配的列名。选择文件后预览读取行数；提交后统计新增、重复和无效行，仅写入有效且不重复的行。扫码报名使用同一去重规则；导入和扫码登记相同去重值时视为同一参与者。去重时去掉首尾空格并忽略英文字母大小写。

每轮包含名称、是否允许前轮中奖者再次参加，以及一到多个奖项。每个奖项包含名称和人数。一次抽奖会从当前合格参与者中随机选出指定人数并一次性保存；一个奖项只抽一次。同轮已获其他奖项者不重复入选。若人数不足，抽奖不发生。服务端持久化抽奖结果，重复请求返回已有结果。

## 主题

每场活动可选择预设风格，设置主色、背景色，上传横幅、背景图和 Logo。报名页和大屏显示同一活动的主题。上传文件限制图片 MIME 类型与大小，不执行上传内容。缺失的素材使用内置默认样式。首版不执行用户上传的 HTML、CSS 或 JavaScript。

## 技术结构

- Node.js 24 服务：原生 HTTP、原生 SQLite、文件静态服务及 JSON API，无外部 npm 运行时依赖。
- SQLite：活动、参与者、抽奖结果。唯一索引保证每场活动的去重值唯一；事务保证一次抽奖的原子性。
- 后台网页：原生 HTML/CSS/JavaScript，负责设置和抽奖控制。
- 大屏网页：只读展示，定时刷新活动及中奖结果。
- 微信小程序：读取活动配置、扫码报名、展示结果。服务器用微信 API 生成活动小程序码；需要组织者提供小程序 AppID 和 AppSecret。

服务端在公司内运行。公网反向代理负责 HTTPS 终止和转发；小程序请求使用已在微信后台配置的公网服务域名。AppSecret 只保存在服务器环境变量中。组织者密码使用加盐哈希；后台操作使用带过期时间的 HttpOnly 会话 Cookie。管理接口要求登录，公开接口仅公开报名所需配置、数量和中奖结果，不公开全量参与者名单。

## 错误与边界

- CSV 行缺少去重值、字段不匹配或值过长时，返回行级错误；重复值计入跳过数。
- 报名关闭、模式不允许、重复报名或字段校验失败时，返回明确提示。
- 活动配置中已有报名数据时，不允许更换去重字段，避免既有记录失效。
- 开始抽奖后，不允许修改轮次和奖项规则；变更活动配置时服务端检查。
- 后一轮须等待前一轮所有奖项完成，确保前轮中奖者资格规则明确。
- 微信凭证缺失或微信码接口失败时，后台显示配置说明或接口错误，不展示无效二维码。
- 自有服务器对外可达、HTTPS、域名及小程序审核/配置由组织者在部署时完成；当前项目不能替代这些外部配置。

## 首版验收

在后台创建两场独立活动；一场导入 CSV 名单，另一场通过小程序报名；两场分别设置字段和去重规则；配置多轮奖项并完成抽奖；中奖排除规则生效；后台和大屏刷新后保留结果；活动各自展示独立主题；配置微信凭证后可生成对应活动小程序码。
